# Expense Categorization & Anomaly Detection

A small, reproducible Python pipeline that cleans messy vendor data from accounting exports (QuickBooks Online / Xero style), categorizes expenses, and flags duplicate payouts and unusual amounts.

> **Data note:** this repo contains only **synthetic, anonymized** data generated by `src/generate_data.py`. No real client records are included. Metrics below are measured on that synthetic data, where the problems were injected with known labels. They show the pipeline works as designed, not how it would score on any real ledger.

## What it does

1. **Vendor cleaning (regex + fuzzy matching):** lowercases, strips legal suffixes (Inc, LLC, Pvt Ltd), removes punctuation, then merges typo variants onto one canonical vendor.
2. **Expense categorization:** TF-IDF character n-grams + logistic regression on vendor and description, evaluated on a held-out split.
3. **Duplicate-payout detection:** same canonical vendor and amount within 3 days of an earlier invoice, even when the vendor name is spelled differently.
4. **Amount-outlier detection:** robust z-score (median/MAD) within each category.
5. **Entry-time validation rule:** `check_duplicate_payout()` blocks a new invoice that would duplicate an existing payout.

## Results (synthetic data, seed 42, 1,070 invoices)

| Check | Result |
|---|---|
| Vendor mapping | 485 raw vendor strings reduced to 15 canonical vendors (15 true vendors) |
| Categorization (25% holdout) | accuracy 1.00, macro F1 1.00* |
| Duplicate payouts | precision 0.974, recall 0.950 (38 TP, 1 FP, 2 FN) |
| Amount outliers | precision 1.000, recall 0.967 (29 TP, 0 FP, 1 FN) |

\*The synthetic descriptions come from a small set of templates, so categorization is easy here. Expect lower scores on real, noisier text.

Full numbers are written to `outputs/metrics.json` on every run.

## Quick start

```bash
git clone https://github.com/<your-username>/expense-anomaly-detection.git
cd expense-anomaly-detection
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python -m src.generate_data     # creates data/raw/sample_invoices.csv
python -m src.pipeline          # writes outputs/ and data/processed/
python -m pytest -q             # runs tests
```

## Using your own data

Provide a CSV with the columns `invoice_id, invoice_date, vendor_raw, description, amount, category`. Evaluation columns (`true_vendor`, `injected_duplicate`, `injected_outlier`) exist only in the synthetic file; adapt `pipeline.py` if your data has no ground-truth labels. Keep real data in `data/private/`, which is git-ignored.

## Limitations

- Fuzzy matching uses a fixed similarity threshold (0.88); very short or very different vendor names may need tuning.
- The categorizer is a simple linear baseline, not a deep model.
- Duplicate logic matches on exact amount; near-equal amounts are not flagged.
